ATS-20 S-meter — dirty region и помехи
Текущая реализация + policy. Ветка ATS-20Plus_next. Baseline 4fe59be.

Policy: S-meter implementation frozen unless hardware testing shows a
perceptual/RF problem. Не трогать ради эстетики (EMA, delta-ramp, compositor).

Уже есть: page 5 only; skip OLED при том же кванте; нет I2C шкалы на крутилке;
SQL на том же RSSI; нет полного framebuffer.
Опора: ATS-20_I2C_burst.txt, ATS-20_SSB_I2C_burst.txt, ATS-20_UI_pixel_grid.txt.
Проблема не в том, что «графический S-meter слишком сложный».
Проблема — полный redraw как реакция на RSSI.

Наивная петля (идиотская для 128×64 I2C):

  RSSI changed
     → redraw entire screen
     → send entire framebuffer
     → I2C traffic
     → CPU busy
     → digital noise

S7→S8: 99% экрана то же. clear / drawEverything / display — абсурд.

Главное

  render(state) → dirty regions → prioritized commit → partial transfer.

Не redraw(). S-meter — первый кандидат: динамический, узкий, визуально важен,
полный кадр ему не нужен. Красивая шкала возможна без OLED-обогревателя
и радиопередатчика по совместительству.

На ATmega328P нет второго 1024-байтного RAM-framebuffer «BASE + OVERLAY».
Tiny4kOLED стримит в SSD1306. Overlay = не трогать чужие pages, не две копии кадра.

------------------------------------------------------------------------
1. Регион, не пиксельный diff

Не бухгалтерия «какой пиксель изменился» — на 328P это дороже отрисовки.

Прямоугольник (факт сетки: page 5, 8 px высотой, под 7-seg pages 2–4):

  Rect smeter = { x: 0, y: 40, w: 128, h: 8 }   // SSD1306 page 5

Dirty: эта page. Остальное не пишется.

Полный кадр: 128×64/8 = 1024 байта данных.
Page 5 целиком: 128 байт (+ команды адресации).
Пользовательский пример 112×8: ~112 байт. Тот же порядок.

Ещё уже: не перерисовывать всю шкалу.

  ████████████░░░░░░░░     S7
  ██████████████░░░░░░     S8
              ↑ только новые сегменты

Цепочка, не pixel-diff:

  S-meter value → quantize → segment index → if changed → update changed segment(s)

Сейчас в коде при смене `val` уходит вся page 5 (глифы S/цифра/+ и ramp 114 колонок).
Следующий шаг: если цифра S та же, слать только хвост ramp (start column = min(old,new)).

------------------------------------------------------------------------
2. Не вешать OLED на сырой RSSI

Si473x шумит: 47 48 47 49 48 47 50. Каждый sample на экран = дрожь и постоянный I2C.

  RSSI → EMA / IIR → quantization → S-meter level → UI

UI только на заметный переход уровня, не на каждый dBµV.

Сейчас: квант в `val` 0..15 (S-unit / +10 dB over S9) и skip OLED если `val == g_sMeterDrawnVal`.
Это hysteresis квантом, не IIR. Дрожь внутри одного сегмента уже отсекается.
IIR нужен, если соседние сегменты всё ещё щёлкают на шуме. Лёгкий EMA в uint8/uint16, не float.

------------------------------------------------------------------------
3. Три частоты (не одна)

  RF measurement   ~10–20 Hz   RSSI/SNR с чипа (SQL может взять тот же sample)
  S-meter model    ~20 Hz      smooth + quantize
  Display commit   5–10 Hz     и только если уровень реально сменился

  Si4732 RSSI
       ▼
  S-meter model (filter, quantize)
       ▼
  value changed?  no → ничего на OLED, display idle
       yes → dirty region → queue → partial update

Poll чипа ≠ paint OLED. Сейчас `showSMeter` раз в 100 ms всегда ходит на Si473x
за RSSI (нужно SQL), но OLED шлёт только при смене `val`. Это уже правильное
разделение на половине пути. Не возвращать «каждые 20 ms redraw display».

Event-driven:

  RSSI changed enough → mark dirty → render region → I2C transfer → idle

не

  every 20 ms: redraw display

------------------------------------------------------------------------
4. Overlay и приоритет (compositor без RAM-сцены)

Стабильный слой: частота, MODE, BW, STEP, VOL, BFO — pages 0–4 и 6–7.
Динамический: S-meter page 5.

Смена RSSI не пересобирает MAIN. TRANSIENT шапки не требует перерисовки шкалы.

Не все виджеты равны, пока крутят:

  P0  frequency / transient input
  P1  mode / BFO
  P2  S-meter
  P3  RSSI numeric (если появится)
  P4  decorative

Scheduler: что стоит отправить на экран прямо сейчас?
Во время tuning: частота — high, S-meter — low / пауза.
Сейчас: пока `g_encoderCount != 0`, фон (S-meter/SQL poll) не идёт. Сохранить.

------------------------------------------------------------------------
5. Display quiet window (экран в RF scheduler)

Реже обновлять — мало. Нужно окно тишины относительно радиокоманд.

Вариант A — после tune:

  Si473x setFrequency / BFO
     → settle
     → RF quiet window
     → тогда display (S-meter / status)

Вариант B — если конкретный SSD1306 гадит в момент acquisition:

  display transfer → idle → Si473x measurement → idle

Выбор A/B — слух/спектр на ДВ и слабом SSB, не догма.
Стык с ATS-20_SSB_I2C_burst.txt: commit частоты и OLED не вперемешку
в одном 10 ms окне без нужды. Фон S-meter на 100 kHz, не i2cFast.

------------------------------------------------------------------------
6. Что уже есть vs что писать

Есть:
  шкала только page 5, не полный кадр;
  skip OLED при том же кванте;
  нет S-meter I2C на крутилке;
  SQL на том же RSSI, что и шкала;
  dirty mark частоты отдельно от шкалы.

Нет (и не делать без hardware fail):
  IIR/EMA; delta-ramp; compositor-приоритеты; RAM overlay.

Когда дойдём — только если hardware test показал проблему. Не рефакторить
ради DRY/эстетики. Не заводить полный framebuffer и pixel-diff.

Не делать:
  clear+full redraw на RSSI;
  привязка каждого sample к пикселю;
  1024-байтный shadow buffer «потому что compositor»;
  S-meter в том же burst 400 кГц, что tuning.
