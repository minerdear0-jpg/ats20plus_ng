ATS-20 I2C noise budget — burst 400 kHz
Ветка ATS-20Plus_next. Baseline прошивки: 4fe59be (плюс этот документ).

История (не путать с HEAD)
  965c5d3 — encoder-first и глобальные 400 кГц. Снято: гармоники SCL на СВ/КВ.

Текущая архитектура (уже в коде, не «potential exit»)
  NORMAL / QUIET   I2C_RUN_HZ 100 kHz
  COMMIT           I2C_FAST_HZ 400 kHz только внутри commitRadioFrequency
                   (SET FREQ / BFO), сразу 100
  SSB patch        500 kHz коротким окном, затем 100

OLED, SQL, S-meter, VOL/BW без commit — 100.
Позже той же схемой: обернуть короткие Si473x-команды (volume, BW, AGC)
Fast→Quiet. Не поднимать clock на всю сессию крутилки, не разгонять OLED.
Это не P0: P0 = NACK/STOP, один эксперимент за раз.

------------------------------------------------------------------------
Принцип

Fast when touching, quiet when listening.

Не выбирать «100 кГц навсегда» vs «400 кГц навсегда».
400 кГц — транспортный ускоритель коротких транзакций, не режим приёма.

Si473x не обязан болтать по I2C, пока слушает уже настроенную частоту.

------------------------------------------------------------------------
Почему 400 кГц больно на ATS-20

I2C не передатчик, но на 400 кГц есть: крутые фронты SCL, пачки SDA/SCL,
гармоники выше фундаментала, импульсы тока в питании 328P, излучение дорожек,
модуляция земли. Front-end у платы бедный, вход легко забивается.

Существующие прошивки уже крутят CLKPR / sleep MCU именно как снижение
радиопомех. Постоянный 400 кГц этому противоречит. Короткий burst — нет:
средняя энергия цифрового мусора падает с duty cycle, не с «магической задержкой».

------------------------------------------------------------------------
Модель скоростей

RADIO_QUIET / IDLE     100 kHz (кандидат quiet 50–61.5 как у diqezit на ДВ)
COMMIT / пакет         400 kHz только на пакете команд
RADIO_SETTLING         сразу 100 kHz
SSB patch              500 kHz, затем restore I2C_RUN_HZ

Не Wire.setClock(400000) глобально.

Интерактив частота: burst 400 в commitRadioFrequency.
Фон (RSSI, SQL, S-meter, status poll): 100.
Экран как часть RF: ATS-20_S-meter_dirty.txt. S-meter frozen unless hardware
test shows a perceptual/RF problem.

Batch: SET FREQ + status в одном окне fast, не чередовать wait/I2C/wait.

------------------------------------------------------------------------
Связь с UI / radio.cpp

Encoder first, OLED сразу, фон не ходит по шине пока крутится крутилка.
SSB: RF_COMMIT_MS 10 — deadline с первого pending, не debounce.
AM/FM: FREQ_COMMIT_MS 70 debounce после последнего тика.
S-meter / SQL / RDS / battery не лезут в I2C на крутилке.
Acceleration 10/100/1k — только после слуха, не превентивно.

Не держать 400 кГц десятки ms «на всякий случай».

Профили (не RSSI-автомат вслепую, не сейчас):
  RF_QUIET     100k, реже OLED, агрессивный sleep
  INTERACTIVE  400k burst + активный дисплей
  NORMAL       100k, периодический status
  SCAN         отдельный короткий burst

------------------------------------------------------------------------
Код

Clock уже setI2CFastModeCustom вокруг commit. Отдельные i2cFast()/i2cQuiet()
не обязательны, если avr-size не выиграет. Фон SQL/S-метр fast не включают.

NACK/STOP ортогонально скорости: ATS-20_I2C_nack_stop.txt. Один commit.

Проверка на железе: ДВ 9 кГц, КВ слабый SSB, крутилка vs idle.
Если burst слышен на ДВ — сузить окно или оставить 100 на LW/MW.

Не делать

Постоянные 400 кГц «потому что быстрее UI».
Переключатель в Settings «I2C 400» как основной UX.
RAII-класс ради скобок.
Привязка 400/100 напрямую к RSSI без профиля чувствительности.
Несколько подсистем в одном эксперименте.
